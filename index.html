Postgres, storage and a console your team can read in Arabic — running in Egypt.

Pyrabase is a backend platform where every project gets its own Postgres, its own object storage and its own API, with the data resident in Egypt and a console built Arabic-first. Pausing means an idle project releases its compute and keeps its data, so you are not paying for a database nobody is using.

Tested by running it, not by promising it.

Each statement below is an automated check that runs against a real cluster. If the behaviour ever changes, the check fails before the change reaches you.

Pause, wake and your data

  • ✓Pausing releases compute — after a pause, nothing of the project is left running (34.46 s)
  • ✓Pausing is not deleting — the database, credentials and stored files all survive
  • ✓Waking ends on a working database, not just a started server: the first successful query arrives in 12.43 s, inside a 60-second limit
  • ✓Your data survives the round trip — a row written before the pause is still there after the wake
  • ✓Services come back only after the database answers, so nothing connects to a database that is not ready
  • ✓Waking a project that was never paused is harmless

Isolation between projects

  • ✓A project writes to and reads back its own storage bucket
  • ✓Another project is denied — and the check only counts that denial once the owner's own access has worked, so a broken system cannot pass as a secure one
  • ✓Every bucket records an owner; a bucket without one would be open to anyone
  • ✓Deleting a project leaves no identity, credentials, access policy or binding behind
